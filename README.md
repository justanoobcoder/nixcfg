# My NixOS Configuration

This repository contains my personal NixOS configuration, structured using a **dendritic pattern** powered by [`flake-parts`](https://flake.parts) and [`import-tree`](https://github.com/vic/import-tree).

This architecture allows for modular evaluation of standard flake outputs, splitting features, overlays, packages, and host configurations into distinct files that are elegantly discovered through `import-tree` rather than manually maintained arrays of imports.

## Project Structure

Every `.nix` file under `modules/` is a flake-parts module picked up automatically by `import-tree`, so adding a feature only means creating a file (and `git add`-ing it, since flakes only see tracked files). Each file defines one `flake.nixosModules.<name>` or `flake.homeModules.<name>`; hosts then choose which ones to import.

```text
modules/
├── parts.nix                 # flake-parts setup (systems, home-manager flake module)
├── common/                   # reusable across hosts and users
│   ├── bundles/              # bundle* modules grouping related features (base, core-system, desktop, dev)
│   ├── nixos/                # NixOS features (one per file, e.g. fonts, sound, unda)
│   ├── home/                 # home-manager features (hm*, e.g. hmGit)
│   ├── overlays/             # nixpkgs overlays; default.nix applies all of them
│   └── packages/             # local packages exposed under `packages.<system>`
├── users/
│   └── hiepnh/
│       ├── default.nix       # nixosModules.userHiepnh: the account, trusted-users, home-manager.users.hiepnh
│       └── home/             # homeModules.userHiepnh* (default.nix imports the rest)
└── hosts/
    └── nixos-pc/
        ├── default.nix       # nixosConfigurations.nixos-pc: the only place listing imported modules
        ├── configuration.nix # host settings (hostname, primary user, stateVersion, …)
        ├── hardware.nix      # generated by nixos-generate-config
        └── features/         # nixosPc* modules specific to this machine (firewall, sudo, suspend, packages, …)
```

### Naming conventions

| Kind | Location | Module name |
| --- | --- | --- |
| Common NixOS feature | `common/nixos/foo-bar.nix` | `nixosModules.fooBar` |
| Common home-manager feature | `common/home/hm-foo.nix` | `homeModules.hmFoo` |
| Bundle | `common/bundles/foo.nix` | `nixosModules.bundleFoo` / `homeModules.bundleFoo` |
| User | `users/<user>/default.nix` | `nixosModules.user<User>` / `homeModules.user<User>` |
| User's home feature | `users/<user>/home/foo.nix` | `homeModules.user<User>Foo` (e.g. `userHiepnhFish`) |
| Host-specific module | `hosts/<host>/features/foo.nix` | `nixosModules.<host>Foo` (e.g. `nixosPcFirewall`) |

Module names share one namespace across the whole flake, and two files defining the same name are
**merged silently** rather than reported, so always use the prefix of the folder a module lives in.

Common modules must not hardcode a user or machine. Modules that act on one user (the unda greeter,
the fcitx5-lotus server, the ydotool group) read `nixcfg.primaryUser`, which `bundleBase` declares and
each host sets in its `configuration.nix`.

### Adding a host

1. Create `modules/hosts/<host>/hardware.nix` from `nixos-generate-config --show-hardware-config`,
   wrapped as `flake.nixosModules.<host>Hardware`.
2. Create `modules/hosts/<host>/configuration.nix` (`flake.nixosModules.<host>Configuration`) with at
   least `networking.hostName`, `nixcfg.primaryUser` and `system.stateVersion`.
3. Create `modules/hosts/<host>/default.nix` defining `flake.nixosConfigurations.<host>`, importing the
   two modules above, `bundleBase`, the users and whichever common features and bundles it needs
   (`nixos-pc/default.nix` is the example).
4. `git add` the new files. CI picks up every `nixosConfigurations` entry on its own.

### Adding a user

1. Create `modules/users/<user>/default.nix` defining `flake.nixosModules.user<User>` with
   `users.users.<user>` and `home-manager.users.<user> = self.homeModules.user<User>`.
2. Create `modules/users/<user>/home/default.nix` defining `flake.homeModules.user<User>` with `home.username`,
   `home.homeDirectory`, `home.stateVersion` and the `hm*`/bundle imports; put personal modules next to it
   as `user<User>*`.
3. Import `self.nixosModules.user<User>` from each host that should have the user.

### Inputs

Inputs are pinned with [tack](https://github.com/manic-systems/tack) in `.tack/pins.toml` and locked in `.tack/pins.lock.json`; `flake.nix` has no `inputs` block and there is no `flake.lock`. Evaluating and building only need Nix (`.tack/default.nix` is plain Nix), while changing pins needs the `tack` CLI:

```sh
tack look            # show upstream drift (-v lists the commits)
tack update [name]   # relock all pins, or one
tack undo            # revert the last tack edit
```

`nix flake update` and `--override-input` do not apply. tack resolves `github:` pins through the GitHub API, which allows 60 requests an hour without a token; set `GH_TOKEN` (e.g. `GH_TOKEN=$(gh auth token) tack update`) if updates run into that limit. See [docs/tack.md](docs/tack.md) for the full workflow.

## Installing on a New Machine

Some flake inputs (`fcitx5-jot`, `keywave`, `unda`, `jon`) are **private GitHub repositories** fetched over SSH, so the installer needs an SSH key registered on GitHub before it can evaluate the flake. Prebuilt binaries of these packages are served from [`justanoobcoder.cachix.org`](https://app.cachix.org/cache/justanoobcoder), so they are downloaded instead of rebuilt (as long as the cache was pushed after the last rebuild), but only if the caches are passed to `nixos-install` (step 6).

The steps below work from the **minimal (no desktop) NixOS ISO**. GitHub login uses the device flow, so you only need a phone or another device with a browser.

### 1. Prepare the live environment

Boot the ISO, connect to the network, then become root (`nixos-install` runs as root, so the SSH key must belong to root):

```sh
sudo -i
nix-shell -p gh git
```

### 2. Authenticate with GitHub

```sh
gh auth login
```

Answer the prompts:

- **Where do you use GitHub?** → `GitHub.com`
- **Preferred protocol for Git operations?** → `SSH`
- **Generate a new SSH key?** → `Yes` (optionally set a passphrase)
- **Title for your SSH key** → something identifiable, e.g. `nixos-installer`
- **How would you like to authenticate?** → `Login with a web browser`

`gh` prints a one-time code. Open <https://github.com/login/device> on your phone, enter the code and approve. `gh` then uploads the new public key to your GitHub account.

Verify:

```sh
ssh -T git@github.com
```

### 3. Partition, format and mount

Partition and mount the target disk under `/mnt` as usual (see the [NixOS manual](https://nixos.org/manual/nixos/stable/#sec-installation-manual-partitioning)).

### 4. Clone the configuration

```sh
mkdir -p /mnt/home/hiepnh
git clone git@github.com:justanoobcoder/nixcfg.git /mnt/home/hiepnh/.nixcfg
```

### 5. Update the hardware configuration

If the hardware differs from the previous machine, regenerate it and merge the relevant parts (filesystems, kernel modules, etc.) into `modules/hosts/nixos-pc/hardware.nix`:

```sh
nixos-generate-config --root /mnt --show-hardware-config
```

### 6. Install

```sh
nixos-install --flake /mnt/home/hiepnh/.nixcfg#nixos-pc \
  --option extra-substituters "https://justanoobcoder.cachix.org https://umbriel.cachix.org https://cache.lantian.pub/lantian https://noctalia.cachix.org" \
  --option extra-trusted-public-keys "justanoobcoder.cachix.org-1:D2/vJZSn8o8Fpsxzbjc9tHo2/D1ejBUqc4r71UvDVyk= umbriel.cachix.org-1:JfNq/2yg2S6D6z4Z2dVSZrZlDPQTKtexB6GAVLD98nw= lantian:WVGO7vsRMSEN+h7Lp7kv6SAmrkEXgUGbbXm7jMDjBuQ= noctalia.cachix.org-1:pCOR47nnMEo5thcxNDtzWpOxNFQsBRglJzxWPp3dkU4="
```

The binary caches in `nix.settings` only take effect once the new system is running, so pass them to
`nixos-install`; without them the CachyOS kernel and the `justanoobcoder/*` packages build from source.

Set the root password when prompted, then set the user password:

```sh
nixos-enter --root /mnt -c 'passwd hiepnh'
```

### 7. Keep the SSH key (optional)

The key generated in step 2 lives in the live environment's RAM and is lost on reboot. Either copy it to the new system:

```sh
mkdir -p /mnt/home/hiepnh/.ssh
cp ~/.ssh/id_ed25519* /mnt/home/hiepnh/.ssh/
nixos-enter --root /mnt -c 'chown -R hiepnh:users /home/hiepnh/.ssh /home/hiepnh/.nixcfg && chmod 600 /home/hiepnh/.ssh/id_ed25519'
```

Or, after rebooting, run `gh auth login` again as `hiepnh` to create a new key, and delete the `nixos-installer` key from <https://github.com/settings/keys>.

### 8. Rebuilding afterwards

Run rebuilds as your user (not `sudo nixos-rebuild`) so private inputs are fetched with your own SSH key:

```sh
nixos-rebuild switch --flake ~/.nixcfg#nixos-pc --sudo
```

### Updating the binary cache

After updating the private inputs (or `nixpkgs`) and rebuilding, push the new builds so the next reinstall can download them:

```sh
nix path-info -r /run/current-system | grep -E 'jot|keywave|unda' | grep -v -- '-source$'
cachix push justanoobcoder <store paths of the main packages>
```
